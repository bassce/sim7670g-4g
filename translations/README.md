# Web 界面语言包

简体中文 `zh-CN.json` 和英文兜底 `en.json` 各包含 250 条文案，版本 `1.0.0`，适用于本项目当前 Web 界面的 `uiSchemaVersion: 1`。这不是固件版本号。

## 使用状态

语言包文案已经制作并校验；**当前设备网页尚未接入语言加载和选择功能**。下载或上传这些文件不会自动改变设备界面。目录中的 `integrationStatus: pending` 用于明确这个边界。

覆盖导航、设备信息、设置、蓝牙连接、OBD 数据编辑、协议与数据类型选项、现有本地 OTA 上传页、参数校验及已定义的蓝牙错误码。翻译已有 OTA 页面不代表新增在线检测或升级功能。未知的浏览器、HTTP、底层库错误通过带 `{detail}` / `{code}` 的兜底文案显示原始信息，不能保证未知原文为中文。

## 文件

- `zh-CN.json`：简体中文包，UTF-8、LF，无 BOM。
- `en.json`：与中文完全相同的键，用作英文兜底。
- `*.json.gz`：相同 JSON 的 gzip 文件；最终接入时选择其中一种传输格式，不要求设备同时存两份。
- `catalog.json`：相对下载路径、文件大小和 SHA-256。gzip 与解压后 JSON 分别提供校验值。
- `messages.tsv`：文案编辑源，三列依次为稳定键、英文、简体中文；服务器保留，设备无需下载。
- `build.py`：生成及校验工具；服务器/开发电脑使用，设备无需下载。

只将语言 JSON 作为数据解析和显示，不执行脚本，不把服务端文案直接作为 HTML 注入。链接和文件名仍由应用控制。新语言必须使用相同键并保留 `{name}`、`{code}`、`{detail}` 等占位符；语言切换时由加载器替换，不能直接交给 Angular 编译为模板。

## 术语与边界

- OBD 配置 `name` 的标签译为“固定标识”，实际字段值不翻译；`description` 的标签译为“显示名称”。
- 车型模板 description 的多语言值由 `pids/` 管理，语言包不覆盖用户自定义 PID 描述。
- 保持 PID、CAN 地址、MQTT 主题、公式变量、函数名和标准单位不变，只翻译显示标签。
- GPS、MQTT、ELM327、ISO、PIN、APN 等技术标识保留，必要时配中文解释。
- `Power` 为“功率”，`Energy` 为“电能”，不混用 kW 与 kWh。
- 休眠文案对应现有其他板型的设置，当前 SIM7670G 节电方案尚未实现。

## 维护和校验

在项目根目录使用 Python 3 运行 `python translations/build.py`。工具检查重复键、空译文、占位符一致性、静态 HTML、动态提示、枚举选项、已定义错误码，以及 gzip 往返；输出确定的 LF JSON 并更新目录校验值。

新增或修改界面时应同步更新文案。现有源代码还使用英文硬编码，后续接入时须按语境使用稳定键，不能只按英文内容匹配：例如设备信息的 `Name` 与 PID 编辑器的 `Name` 含义不同。

GitHub 与 Gitea 镜像应同步整个 translations 目录。客户端选定并缓存一种语言后可离线显示；英文兜底、下载替换保护和语言选择将在加载器中实现。
